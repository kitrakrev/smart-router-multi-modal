Smart Router Multi-Modal

Multi-modal LLM router with vision, tools, and real-time tracing — routes each query to the optimal model by embedding similarity to decision exemplars.

View on GitHub← kitrakrev.github.io

What it does

An LLM routing layer that sits between an application and multiple LLM providers. Instead of hardcoding which model handles which query, it extracts signals from the query, matches it to a task type, and picks the cheapest capable model — complex math goes to reasoning models, simple QA to small local models, vision queries to multimodal models.

  • 9 signal extractors: keyword, domain, complexity, language, safety, PII, vision, tool, modality
  • Budget strategies: cheapest_capable, quality_first, balanced, performance_weighted
  • Adaptive, EMA-based health tracking that auto-disables and recovers degraded models
  • Dynamic model registry, hot-reloadable YAML config, OpenAI-compatible /v1/chat/completions
  • Real-time dashboard (traces, pipeline, models, stats, sessions, config, datasets) and 11 built-in tools

How it works

Query → Guardrails → Signal extractors → Decision matcher → Capability filter → Budget selection → Model
  • Layer 1 — what task? Decision exemplars in config/config.yaml are embedded with all-MiniLM-L6-v2; the query is matched to the nearest decision centroid by cosine similarity (vLLM-SR style).
  • Layer 2 — which model? The model pool is filtered to those with every required capability (e.g. [vision], [reasoning, code]), then the decision's budget strategy picks one.
  • Layer 3 — how to call? The decision's inference config (temperature, max_tokens, reasoning, thinking tokens) is passed through to the model call.
  • Safety guardrails (jailbreak, PII) run first; adaptive routing tracks model health over time.
